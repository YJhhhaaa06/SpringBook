# 运行手册（本机 / Windows / Linux）

> 面向"把项目拉起来"这件事：数据库在哪、怎么起、换台机器怎么起、出问题看哪里。
> 接口与业务口径见 `.docs/接口文档.md`，前端设计见 `.docs/第三版实施方案.md`。

## 一、当前这台机器的现状

应用的数据库**在 Docker 容器里**，不在宿主机上：

| 项 | 值 |
|---|---|
| 容器名 | `springbook-mysql`（镜像 `mysql:8.4`） |
| 宿主机端口 | `127.0.0.1:3307` → 容器内 `3306` |
| 库 / 账号 | `springbook` / `springbook`、口令 `springbook`（root 口令 `root`） |
| 数据卷 | 命名卷 `springbook_springbook-mysql-data` → 容器 `/var/lib/mysql` |
| 应用连接串 | `jdbc:mysql://localhost:3307/springbook?characterEncoding=utf8&serverTimezone=Asia/Shanghai...` |

宿主机 3306 被原生 `mysqld` 占用过，所以对外映射到 **3307**；容器之间通信仍走标准的 `3306`。

应用侧的连接参数全都可以用环境变量覆盖（`src/main/resources/application.yaml`）：

```
DB_HOST=localhost   DB_PORT=3307   DB_NAME=springbook
DB_USER=springbook  DB_PASSWORD=springbook
```

> 首次启动不需要手工建库建表：Flyway 会按 `src/main/resources/db/migration/` 依次执行 `V1__init.sql`、`V2__loan_fine_status.sql`，`AdminInitializer` 再创建默认管理员 `admin`。

## 二、路线 A：宿主机跑应用（开发用，改代码即时生效）

前置：**JDK 25**（`pom.xml` 的 `java.version=25`）、Docker。Maven 用仓库自带的 `mvnw`，不必单独装。

### Linux / macOS（bash）

```bash
# 1. 只起数据库
docker compose up -d

# 2. 起应用（JWT_SECRET 必填，缺失会 fail-fast 拒绝启动）
JWT_SECRET='至少32字节的随机串' ADMIN_PASSWORD='admin123' \
  ./mvnw spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8080"

# 3. 打开 http://localhost:8080/
```

打包运行（不经过 Maven 插件，启动更快）：

```bash
./mvnw -DskipTests package
JWT_SECRET='...' "$JAVA_HOME/bin/java" -jar target/SpringBook-0.0.1-SNAPSHOT.jar --server.port=8080
```

### Windows

PowerShell（环境变量只在当前窗口有效）：

```powershell
docker compose up -d

$env:JWT_SECRET   = "至少32字节的随机串"
$env:ADMIN_PASSWORD = "admin123"
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.jvmArguments=-Dserver.port=8080"
```

Git Bash（与 Linux 写法一致）：

```bash
JWT_SECRET='...' ADMIN_PASSWORD='admin123' ./mvnw spring-boot:run \
  -Dspring-boot.run.jvmArguments="-Dserver.port=8080"
```

打包运行：

```powershell
.\mvnw.cmd -DskipTests package
$env:JWT_SECRET = "..."
& "$env:JAVA_HOME\bin\java.exe" -jar target\SpringBook-0.0.1-SNAPSHOT.jar --server.port=8080
```

> ⚠️ 如果 `JAVA_HOME` 没配，`.\mvnw.cmd` 会报 "JAVA_HOME not found"。JDK 25 装好后新建终端再试。

## 三、路线 B：全 Docker（换机器 / 演示，一条命令）

只要装了 Docker，不装 JDK 也能跑。`compose.yaml` 里的 `app` 服务挂在 `full` profile 下，默认不启动，不影响宿主机开发。

### 3.1 本机日常：记住两条命令就够

在 `.env` 里打开 `COMPOSE_PROFILES=full`（`cp .env.example .env` 后取消该行注释）之后：

```bash
docker compose up -d      # 启动：mysql + app 一起起来
docker compose down       # 关闭：两个容器一起移除（数据保留）
```

此时 `ps` / `logs` / `stop` / `start` 也都不用再写 `--profile full`。

### 3.2 不带 profile 会怎样（实测）

| 命令 | 实际效果 |
|---|---|
| `docker compose up -d` | 只起 mysql |
| `docker compose stop` | **只停 mysql，app 还在跑**（随后因连不上库报错） |
| `docker compose start` | 只起 mysql |
| `docker compose down` | **删掉 mysql，app 变成孤儿容器**，网络删不掉（`Resource is still in use`），下次 `up` 会重建库并重新探活 |

所以不带 `COMPOSE_PROFILES=full` 时，命令必须写成 `docker compose --profile full <cmd>`；两条路不要混用。

### 3.3 从零构建（新机器 / 改了代码）

```bash
# 1. 准备变量（JWT_SECRET 必填，.env 已被 gitignore）
cp .env.example .env
#   Linux:  sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -base64 48)|" .env
#   Windows: 手动把 JWT_SECRET= 后面填上随机串（PowerShell: [Convert]::ToBase64String((1..48|%{Get-Random -Max 256}))）

# 2. 构建并启动（mysql + app）
docker compose --profile full up -d --build

# 3. 看状态与日志
docker compose --profile full ps
docker compose logs -f app

# 4. 打开 http://localhost:8080/
```

> 镜像里跑的是构建那一刻的代码：**改了后端或前端之后必须加 `--build`**，否则 `up -d` 会用旧镜像（`docker compose up -d --build app` 只重建应用）。

### 3.4 停止、重启与数据的去留

```bash
docker compose stop      # 停容器，保留容器与数据；start 可以秒回
docker compose start
docker compose down      # 移除容器与网络，数据卷保留（下次 up 数据还在）
docker compose down -v   # ⚠️ 连数据卷一起删，库清空
```

| 操作 | 容器 | 数据（命名卷） |
|---|---|---|
| `stop` / `start` | 保留 | 保留 |
| `down` | 移除，`up` 时重建 | **保留** |
| `down -v` | 移除 | **删除** |
| Docker Desktop 重启 | `restart: unless-stopped` 会自动拉起（显式 `stop` 过的不会） | 保留 |


### 3.5 镜像构成与体积

镜像内部：多阶段构建（`maven:3.9-eclipse-temurin-25` 编译 → `eclipse-temurin:25-jre` 运行），容器内以非 root 用户运行，只暴露 8080；前端静态资源已经在 jar 里，**没有独立的前端服务要起**。

> 首次 `--build` 要在容器里重新解析依赖，本机实测约 **9 分钟**（之后改代码重建只走编译层，几分钟内）；应用镜像 545 MB（不含 MySQL 的 1.1 GB 镜像）。

容器与宿主机的差异只有一处：容器内用服务名 `mysql:3306` 连库，不走宿主机的 3307 映射（已写进 compose 的 `environment`）。

## 四、路线 C：不用 Docker，接已有的 MySQL 8.4

适合环境里已经有数据库的情况。要求 MySQL **8.4**（Flyway 迁移用了 `utf8mb4_0900_ai_ci` 与 MySQL 8 语法）。

```bash
# 1. 建库与账号（在目标 MySQL 上执行一次）
CREATE DATABASE springbook DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'springbook'@'%' IDENTIFIED BY 'springbook';
GRANT ALL PRIVILEGES ON springbook.* TO 'springbook'@'%';
FLUSH PRIVILEGES;

# 2. 用环境变量指过去，其余照旧
DB_HOST=10.0.0.5 DB_PORT=3306 DB_NAME=springbook DB_USER=springbook DB_PASSWORD=springbook \
JWT_SECRET='...' "$JAVA_HOME/bin/java" -jar target/SpringBook-0.0.1-SNAPSHOT.jar
```

表结构与初始数据由 Flyway 自动建立，不需要导入 SQL。

## 五、数据、备份与重置

```bash
# 备份（导出到当前目录）
docker exec springbook-mysql mysqldump -uspringbook -pspringbook springbook > springbook.sql

# 还原
docker exec -i springbook-mysql mysql -uspringbook -pspringbook springbook < springbook.sql

# 连进去看看
docker exec -it springbook-mysql mysql -uspringbook -pspringbook springbook

# ⚠️ 清库重来：会删掉命名卷里的全部数据
docker compose --profile full down -v
```

换个环境"带数据过去"：把 `springbook.sql` 拷走，在新环境先 `docker compose up -d`，再按上面的还原命令导入（Flyway 记录表也在里面，版本会接上）。

## 六、环境变量速查

| 变量 | 默认 | 说明 |
|---|---|---|
| `JWT_SECRET` | 无（**必填**） | HS256 签名密钥，≥32 字节；缺失直接拒绝启动 |
| `ADMIN_PASSWORD` | `admin123` | 首次启动创建 `admin` 时用的口令 |
| `DB_HOST` / `DB_PORT` | `localhost` / `3307` | 数据库地址 |
| `DB_NAME` / `DB_USER` / `DB_PASSWORD` | `springbook` ×3 | 库名与账号 |
| `MYSQL_PORT` | `3307` | 仅 compose：宿主机映射端口 |
| `APP_PORT` | `8080` | 仅 compose：应用对外端口 |
| `COMPOSE_PROFILES` | 空 | 仅 compose：填 `full` 后普通 `up/stop/down/ps/logs` 也作用于 app 容器 |
| `SERVER_PORT` | `8080` | 应用端口（等价于 `--server.port`） |
| `book.loan.days` 等 | 见 `application.yaml` | 借期 30 天、罚款 50 分/天、保留 48 小时、借阅上限 5；用 `--book.loan.max-borrowing=3` 这类参数覆盖 |

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动即报 `缺少 JWT_SECRET 环境变量，拒绝启动（fail-fast）` | 没设 `JWT_SECRET`。设上再启动（compose 环境写进 `.env`） |
| `Port 8080 was already in use` | 上一个进程没退干净。`netstat -ano \| grep :8080`（Windows 用 `netstat -ano \| findstr :8080`）找到 PID 后结束；或换 `--server.port=8081` |
| `Communications link failure` / `Connection refused` | 数据库没起或端口不对。`docker compose ps` 看 `springbook-mysql` 是否 healthy；宿主机连 3307，容器间连 3306 |
| `/actuator/health` 报 `DOWN` 且日志里有 `Connection refused` | 同上，先确认 MySQL 起来（容器启动后约 10-20 秒才可用） |
| 打开页面 404 / 白屏 | 访问的是 `/`；前端资源随 jar 发布，确认启动的是本项目 jar（`GET /js/app.js` 应返回 200） |
| 演示数据不是我想要的 | `python tools/seed_demo_data.py` 会灌入演示数据（幂等）；`docker compose down -v` 可清空重来 |
| 时间是 UTC，差 8 小时 | 容器与 JVM 都按 `TZ=Asia/Shanghai` 配；部署到 UTC 环境时显式传 `-Duser.timezone=Asia/Shanghai` |
| 语言/乱码 | 库与连接都用 utf8mb4；确认客户端也用 UTF-8（Windows 终端 `chcp 65001`） |

## 八、最小启动清单（换新机器的顺序）

1. 装 Docker（Windows 用 Docker Desktop，Linux 用 docker + compose 插件）；
2. 装 JDK 25（走路线 B 可跳过）；
3. `git clone` 项目 → `cd SpringBook`；
4. 路线 B：`cp .env.example .env`（填 `JWT_SECRET`，并取消 `COMPOSE_PROFILES=full` 的注释）→ `docker compose up -d --build`；
   路线 A：`docker compose up -d` → `JWT_SECRET=... ./mvnw spring-boot:run`；
5. 浏览器开 `http://localhost:8080/`，用 `admin` / `ADMIN_PASSWORD` 登录；
6. 想验证功能完整性：`python tools/seed_demo_data.py` 造演示数据，或直接手工建书建读者。

## 九、两条路线的验证记录（2026-10-20）

| 检查 | 路线 A（宿主机 JDK 25） | 路线 B（全 Docker） |
|---|---|---|
| `GET /actuator/health` | `UP` | `UP`（容器启动约 5 秒后） |
| `GET /`（前端入口） | 200 | 200 |
| `./mvnw -o test` | 58/58 通过 | —（镜像内 `-DskipTests`） |
| `python tools/ui_acceptance.py` | 25/25 通过 | **25/25 通过** |
| 缺 `JWT_SECRET` | 启动失败并打印「缺少 JWT_SECRET 环境变量，拒绝启动」 | 同上（容器内同样 fail-fast） |
| 连的数据库 | 宿主机 `127.0.0.1:3307` → 容器 | 容器网络 `mysql:3306` → 同一命名卷 |

两种方式共用同一个数据卷 `springbook_springbook-mysql-data`，所以在两边的数据是一致的；**不要同时启动两者**（都会抢 8080，前者是宿主机进程、后者是容器）。
