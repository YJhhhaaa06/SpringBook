# 开发者手册

给维护者看的。只想把系统跑起来的话，看 [01 快速开始](01-快速开始.md) 就够了。

## 本机开发环境

数据库在容器里，**宿主机端口 3307**，不是 3306：

```bash
docker start springbook-mysql     # 容器停着会连不上
docker compose up -d              # 或用这条，只起 mysql（app 在 full profile 下）
```

| 项 | 值 |
|---|---|
| 容器名 | `springbook-mysql`（镜像 `mysql:8.4`） |
| 端口映射 | `127.0.0.1:3307` → 容器 `3306` |
| 库 / 账号 | `springbook` / `springbook`，口令 `springbook`（root 口令 `root`） |
| 数据卷 | 命名卷 `springbook_springbook-mysql-data` |

宿主机 3306 上曾经装过原生 `mysqld`，所以对外映射到 3307。应用侧全部可用环境变量覆盖，默认值写在 `application.yaml`。

本机 `java` 可能不在 `PATH` 里，只有 `JAVA_HOME`。起 jar 用：

```bash
"$JAVA_HOME/bin/java.exe" -jar target/SpringBook-0.0.1-SNAPSHOT.jar --server.port=8080
```

## Docker profile 的行为

`compose.yaml` 里 `app` 服务挂在 `full` profile 下，默认不启动。这个设计是为了日常开发只起数据库，不让应用容器抢 8080。

不带 profile 时各命令的实际效果：

| 命令 | 实际效果 |
|---|---|
| `docker compose up -d` | 只起 mysql |
| `docker compose stop` | **只停 mysql，app 仍在跑**，随后因连不上库报错 |
| `docker compose start` | 只起 mysql |
| `docker compose down` | **删掉 mysql，app 变成孤儿容器**，网络删不掉（`Resource is still in use`） |

所以要么每条命令都写 `--profile full`，要么在 `.env` 里写 `COMPOSE_PROFILES=full` 一次性解决。两条路不要混用。

## 镜像构成

多阶段构建：`maven:3.9-eclipse-temurin-25` 编译 → `eclipse-temurin:25-jre` 运行。容器内以非 root 用户运行，只暴露 8080。前端静态资源已打进 jar，没有独立的前端服务。

| 项 | 数值（2026-10-20 实测） |
|---|---|
| 首次 `--build` | 约 9 分钟（容器内重新解析依赖） |
| 之后改代码重建 | 几分钟（只走编译层） |
| 应用镜像 | 545 MB |
| MySQL 镜像 | 1.1 GB |

容器与宿主机的唯一差异：容器内用服务名 `mysql:3306` 连库，不走 3307 映射。这一点已写进 compose 的 `environment`。

## 迁移文件的纪律

**已经发布出去的迁移脚本不能再改**，哪怕只是改一行注释。Flyway 会比对校验和，换一台机器首次启动就会直接失败：

```
Validate failed: Migration checksum mismatch
```

改动迁移文件后，本地库需要同步：

```sql
DELETE FROM flyway_schema_history WHERE version = '<改动的版本>';
```

重启后该版本会重新执行。但如果是 V1 / V2 这种改表结构的，删记录重跑会因表已存在而失败，正确做法是重建库。

### V3 种子数据是脚本生成的

不要手改 `V3__demo_seed.sql`，改生成器：

```bash
python tools/gen_v3_seed.py
```

它从 `tools/seed_library_demo.py` 的 `BOOKS` / `HEROES` 读取清单，输出完整 SQL。这样书目和读者只有一份定义，不会漂移。

生成器里的几个约定：

- 所有插入都带 `WHERE @seed = 1`，`@seed` 由 `loans` 表是否为空决定，避免污染已有业务数据的开发库；
- 库存不手写，末尾统一用 `total_copies - 在借数` 反算；
- 日期用 `DATE_SUB(NOW(), INTERVAL n DAY)`，不写死绝对值。

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `JWT_SECRET` | 空 → 内置演示密钥 | 留空时打 WARN 后继续启动；正式部署必须覆盖 |
| `ADMIN_PASSWORD` | `admin123` | 首次启动创建 `admin` 时的口令 |
| `DB_HOST` / `DB_PORT` | `localhost` / `3307` | 数据库地址 |
| `DB_NAME` / `DB_USER` / `DB_PASSWORD` | `springbook` ×3 | 库名与账号 |
| `MYSQL_PORT` | `3307` | 仅 compose：宿主机映射端口 |
| `APP_PORT` | `8080` | 仅 compose：应用对外端口 |
| `COMPOSE_PROFILES` | 空 | 仅 compose：填 `full` 后普通命令也作用于 app |
| `SERVER_PORT` | `8080` | 应用端口，等价于 `--server.port` |

业务参数在 `application.yaml` 的 `book.*`：借期 30 天、罚款 50 分/天、预约保留 48 小时、单人最多在借 5 本。可用 `--book.loan.max-borrowing=3` 这类命令行参数覆盖。

## 验证记录

2026-10-20 两条路线各跑过一遍：

| 检查 | 宿主机 JDK 跑 jar | 全 Docker |
|---|---|---|
| `GET /actuator/health` | `UP` | `UP`（容器启动约 5 秒后） |
| `GET /` | 200 | 200 |
| `./mvnw -o test` | 58/58 通过 | —（镜像内 `-DskipTests`） |
| `python tools/ui_acceptance.py` | 25/25 通过 | 25/25 通过 |
| 缺 `JWT_SECRET` | 启动失败并打印原因 | 同上 |

> 最后一行是当时的旧行为。现在缺 `JWT_SECRET` 会回退到内置演示密钥并打 WARN，不再拒绝启动。

两条路线共用同一个数据卷，所以数据一致；**不要同时启动**，都会抢 8080。

## 制作分发包

```bash
./mvnw -DskipTests package
cp target/SpringBook-0.0.1-SNAPSHOT.jar release/SpringBook.jar
```

然后压缩 `release/` 目录：

```
SpringBook/
├── SpringBook.jar          ← 从 target 复制，注意版本号要去掉
├── 启动.bat
├── 启动.sh
├── application.properties  ← 确认端口是 3306、密码是占位符
└── README.md               ← 从根目录复制
```

检查两件事：

1. `release/application.properties` 里的 `spring.datasource.password` 是占位符，不是本机真实口令；
2. `release/SpringBook.jar` 是**本次构建**的产物，不要用上一次的旧包。

`release/*.jar` 已在 `.gitignore` 里，不会误提交。
