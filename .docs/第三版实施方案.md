# 第三版实施方案（前端）

> 依据 `.docs/第三版候选清单.md` 的结论：**这一版做前端，不做缓存**。
> 约束：不改后端接口契约；58 个集成测试保持全绿（本次实跑 58/58）。
> 交付形态：随应用一起发布的单页控制台，浏览器打开 `http://localhost:8080/` 即为前端入口。

## 一、范围判断

| 事项 | 结论 | 说明 |
|---|---|---|
| 单页控制台（检索/借还/预约/罚款/读者/账户） | **做** | 覆盖第二版 21 个接口中所有面向使用者的能力 |
| 后端 CORS | **不做** | 前端由 Spring Boot 从 `classpath:/static/` 同源托管，不产生跨域 |
| 构建工具（npm / Vite / 打包） | **不做** | 原生 ES Module + 原生 CSS，零构建、零依赖，离线可用 |
| 读者注销接口（候选清单 §3-1） | **不做（本期）** | 属后端契约变更：需新增 `DELETE /api/readers/{id}`、补集成测试、同步更新接口文档；且 `SecurityConfig` 目前没有 `DELETE /api/readers/**` 规则，新端点会落到「已认证即可」分支，等于让 READER 能删读者。收益与风险不匹配，留待下一版单独做 |
| 缓存 / Redis、定时任务 | **不做** | 沿用候选清单结论 |

后端代码零改动，只在 `src/main/resources/static/` 下新增前端资源。

## 二、技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 部署形态 | 静态资源随 Spring Boot 打包，同源访问 | 免 CORS、免额外进程；`GET /` 直接落到 `static/index.html` |
| 路由 | hash 路由（`#/books`、`#/loans?readerId=3`） | 刷新不依赖服务端 SPA fallback，`SecurityConfig` 的 `anyRequest().permitAll()` 也无须改动 |
| 技术栈 | 原生 ES Module + 原生 CSS 变量 | 单机课程项目，引入框架只增加构建链与依赖面；模块化已足够分层 |
| 登录态 | JWT 存 `localStorage`，身份由令牌载荷解析 | 后端登录/注册只返回 `token` + `expiresInSeconds`，`username`/`role`/`readerId` 都在载荷里 |
| 401 处理 | 统一清理会话 + 广播 `sb:unauthorized` → 跳登录并提示「登录已过期」 | `40100`（凭证无效/过期）与 `40101`（口令错误）用 code 区分，后者留在表单里提示 |
| 错误提示 | 接口文档 §7 错误码全表映射，另配一句「下一步建议」 | 业务码是唯一稳定的语义来源，前端不靠 HTTP 状态猜 |
| 参数校验 | `40001` 的 `data`（字段→提示）落到对应输入框下方 | 后端已给出字段级明细，弹 toast 会丢掉信息 |
| 金额 | 一律用 `*Cents` 计算、`*` 字段展示；输入按「元」收，提交时乘 100 取整 | 避免浮点误差，与后端口径一致 |

## 四、页面与角色矩阵

| 页面 | 路由 | READER | ADMIN | 主要接口 |
|---|---|---|---|---|
| 图书检索 | `#/books` | 检索、借阅、预约/取消、看队列 | 检索、代办借阅/预约、新增/编辑/调册下架/删除、看队列 | `GET/POST/PUT/PATCH/DELETE /api/books**`、`/api/reservations` |
| 我的借阅 / 借阅管理 | `#/loans` | 只看自己的记录、还书 | 全量记录、按读者筛选、代办还书、缴罚款 | `GET /api/loans`、`POST /api/loans/{id}/return`、`.../fine/pay` |
| 读者管理 | `#/readers` | —（访问被拦回图书检索） | 分页检索、新增、改资料、冻结/解冻、详情（欠款+在借） | `GET/POST/PUT /api/readers**` |
| 我的账户 | `#/account` | 档案、在借、欠款、改密 | 账号信息、改密 | `GET /api/readers/{id}`、`PUT /api/auth/password` |
| 登录 / 注册 | `#/login` | 匿名 | 匿名 | `POST /api/auth/login`、`/register` |

## 五、关键交互与取舍

### 1. 借阅与预约的「代办」入口
READER 的 `readerId` 取自令牌，接口不传即自身；ADMIN 的令牌没有 `readerId`，所以 `POST /api/loans`、`/api/reservations` 必须显式指定读者。前端的做法是：同一个弹层，ADMIN 多出「读者选择器」（关键词走 `GET /api/readers?keyword=`，点选后提交），未选择时内联报错而不是发一个注定 403/400 的请求。

### 2. 预约的可见性（接口缺口下的折中）
后端只提供「按书查队列」（`GET /api/books/{id}/reservations`），**没有「按读者查预约」**，因此做不出独立的「我的预约」页。前端把预约状态叠加到图书卡片上：加载每一页卡片后并行拉取这 9 本书的队列，找出「我的」那条活跃预约，得到

- `WAITING` → 「排队中 · 第 N 位」
- `READY` → 「到书待取，保留至 47:59:12」（秒级倒计时，到期变「已过期」）

这样读者既能看见自己的排队位置，也不需要记住自己约了哪本。代价是每页多 N 个队列请求（N=9，单机可接受）；若后续补了按读者查预约的接口，应改为独立页面。

### 3. 库存与预约的语义对齐
READY 预约会占用一个 `available_copies`，所以「可借=0 但我是 READY」时仍应能借出（后端履约路径不扣库存）。前端据此把「借阅」按钮的可用条件定为 `availableCopies > 0 || 我的预约是 READY`，与后端行为一致。

### 4. 还书结算
`POST /api/loans/{id}/return` 的响应带 `overdueDays`/`fineCents`，前端用结果弹层把「逾期 N 天 → 罚款 X 元（待缴）」讲清楚，并提示两件容易被忽略的副作用：逾期归还**自动冻结读者**；若队列非空，队首立刻转为「到书待取」。ADMIN 在弹层里可直接「立即缴纳」。

### 5. 候选清单里点名的边界
| 清单项 | 前端处置 |
|---|---|
| §3-6 READY 倒计时 | 卡片与队列抽屉都用全局时钟秒级刷新，剩 30 分钟内标红 |
| §3-7 `40912` 版本冲突 | 错误码表映射为「图书信息已被其他操作修改，请重试」，附建议「刷新后重新提交」，顶栏常驻刷新按钮 |
| §3-4 手机号/用户名格式 | 注册与读者新增/编辑做 11 位大陆手机号校验并按 `40001` 内联展示；用户名只按后端 3-50 长度约束提示 |
| §3-1 读者注销 | 本期不做（见 §一） |
| §3-2/§3-3 登录锁定、登出失效 | 不做，前端不假装有：退出仅清本地令牌，改密后旧令牌在过期前仍有效，账户页明确写出 |

### 6. 状态与文案口径
- 借阅状态：`在借` / `逾期未还`（红色，`overdue` 由后端实时派生）/ `已归还`
- 罚款：`无罚款` / `待缴`（红）/ `已缴`
- 预约：`排队中` / `到书待取` / `已借出` / `已取消` / `已过期`
- 读者：`正常` / `已冻结`（解冻按钮旁明确提示「解冻绕不过罚款禁借」）

### 手工验收建议（走通一条完整链路）
1. `admin` 登录 → 图书检索「新增图书」（给了书号/册数/价格）；
2. 用注册页建读者账号（如 `reader01`）→ 自动登录为 READER；
3. 读者检索该书 → 借阅 → 「我的借阅」看到在借与应还时间；
4. 管理员另建一本 1 册的书、让读者借走 → 读者再点「预约」→ 卡片显示「排队中 · 第 1 位」；
5. 管理员还书 → 读者卡片变「到书待取」并开始 48 小时倒计时 → 读者借出（履约）；
6. 造逾期：把 `loans.due_at` 改到过去 → 还书 → 弹层显示罚款金额 → 管理员「缴罚款」→ 读者解冻。

## 八、已知边界

- **预约没有「我的」页**：受接口所限（见 §5-2），当前以图书卡片 + 队列抽屉承载。
- **无读者注销**：本期未做，做的时候记得同步 `SecurityConfig` 的 `DELETE /api/readers/**` 规则。
- **改密后旧令牌仍有效**：无状态 JWT 的固有代价，前端不掩盖，账户页已注明。
- **令牌 2 小时不可续期**：到期即回登录页，不做静默续签。
- **时区**：时间按服务器本地时区（Asia/Shanghai）返回，前端按浏览器本地时间解析，两地一致时才准确。
