# 图书信息管理系统 — 技术选型与设计决定

> 状态：**第一版已实现（2026-10-19）**：29 个集成测试全绿（Testcontainers + Flyway 真迁移），冒烟链路 16/16 通过（`tools/smoke.py`）。接口明细见 `.docs/接口文档.md`。
> 依据：`.docs/原始需求.md`；本地 Maven 仓库（`C:\Users\ASUS\.m2\repository`）实际盘点结果。

## 1. 需求边界

**核心功能**：图书信息（书名、书号、可借阅数量、价格）的插入、删除、检索；存储图书与借阅人信息；借阅与归还。
**扩展功能**：可借数量为 0 时允许预约；逾期未还罚款。
**明确不做**：登录/鉴权/角色（需求未提）；前端界面（纯 REST）；图书信息修改之外的管理后台能力。

## 3. 关键决策记录

### 3.1 金额一律以「分」为整数存储
- `books.price_cents`、`loans.fine_cents` 均为 `INT`，单位分。
- 罚款单价 0.5 元/天 = **50 分/天**；罚款 = 逾期天数 × 50，**封顶为该书的 `price_cents`**。
- 全程禁止 `float`/`double`；仅在出参时用 `BigDecimal.valueOf(cents).movePointLeft(2)` 转元。
- 逾期天数按「不足一天计一天」向上取整：`ceil((now - due_at) / 1 天)`。

### 3.2 借阅期限 30 天，可配置
`book.loan.days=30`，归还截止时间 = 借出时刻 + 30 天，落库到 `loans.due_at`（不做动态计算，便于后续改规则时历史数据不变）。

### 3.3 逾期状态不落库，按 `due_at` 派生
`loans.status` 只有 `BORROWED` / `RETURNED`；「是否逾期」由 `due_at < now && returned_at IS NULL` 实时判定，避免引入定时任务与状态不一致。罚款金额在**归还那一刻**结算并写入 `fine_cents`。

### 3.4 预约为 FIFO 队首优先
- 仅当 `available_copies = 0` 时允许预约，否则直接提示可借。
- 状态机：`WAITING → READY → FULFILLED`，旁路 `CANCELLED`、`EXPIRED`。
- 归还时：若队列非空，队首 `WAITING` 置 `READY`，并写入 `hold_until = now + 48h`（`book.reservation.hold-hours=48`）。
- `READY` 超过 `hold_until` 未取：置 `EXPIRED`，自动顺延下一位。采用**惰性清理**（在借书、还书、查预约时触发），不引入定时任务。
- 同一读者对同一本书只能有一条活跃预约（`WAITING`/`READY`），用服务层 + 事务内校验保证。

### 3.5 并发控制用「条件更新」，不用悲观锁
借出：`UPDATE books SET available_copies = available_copies - 1 WHERE id = ? AND available_copies > 0`，受影响行数为 0 即库存不足，抛业务异常。
归还：`UPDATE books SET available_copies = available_copies + 1 WHERE id = ? AND available_copies < total_copies`。
`books` 表带 `version` 列（乐观锁），仅在需要整体更新图书信息时使用。

### 3.6 统一响应与异常
`Result<T> { code, message, data }`，成功 `code=0`；业务异常继承 `BizException` 携带 `ErrorCode`，由 `@RestControllerAdvice` 统一转换；参数校验失败映射为 `40001` 并返回字段级明细。

### 3.7 测试策略
- 集成测试用 Testcontainers 拉起 `mysql:8.4`，通过 `@ServiceConnection` 注入数据源，Flyway 在容器内真实执行迁移脚本。
- 覆盖重点：库存扣减并发（多线程抢最后一本）、归还触发队首 `READY`、罚款封顶、逾期天数向上取整。
- 不使用 H2（方言与锁行为差异会掩盖真实问题）。

### 3.8 鉴权：无状态 JWT（第一版即纳入）
需求原文未提鉴权，但作为对外接口必须有身份边界，第一版直接引入，角色细分留到后续。

- **方案**：`spring-boot-starter-security` 7.1.1 提供过滤链与 `BCryptPasswordEncoder`，`java-jwt` 4.6.1 负责签发/校验，走自定义 `OncePerRequestFilter` 解析 `Authorization: Bearer <token>`，不使用 Session。
- **不选 Spring Security 内置 JwtDecoder**：需要 `spring-security-oauth2-jose` + `spring-security-oauth2-resource-server`，本地仓库没有。
- **账号模型**：独立 `accounts` 表（`id, username, password_hash, role, reader_id, status`）。`role` 取 `READER` / `ADMIN`；`READER` 账号通过 `reader_id` 关联 `readers` 表，`ADMIN` 为 `NULL`。读者身份与借阅人资料分离，避免把密码塞进业务表。
- **Token**：HS256，载荷含 `sub`(accountId)、`role`、`readerId`、`iat`、`exp`，有效期 2 小时，不做 refresh token（第一版）。
- **密钥**：只从环境变量 `JWT_SECRET` 读取，**不写进任何提交文件**；缺失则启动失败（fail-fast）。本地通过 IDE 运行配置或 `.env` 注入。
- **放行范围**：`POST /api/auth/login` 与 `/actuator/health` 匿名；`/api/admin/**` 要求 `ADMIN`；其余 `/api/**` 要求已认证。
- **后续扩展**：角色细分时只需在同一 `SecurityFilterChain` 上加 `hasRole` 规则，账号表已预留 `role`。
- **状态（2026-10-19 修订）**：已随第一版接线完成（提交 df1da50）——pom 已含 `spring-boot-starter-security` 与 `java-jwt` 4.6.1，`SecurityConfig` 过滤链 + `JwtAuthFilter` + `AuthService`/`JwtService` 全部落地。实际放行口径为：图书写操作（POST/PUT/DELETE `/api/books/**`）与新增读者（POST `/api/readers`）要求 ADMIN，`/api/auth/login` 与 `/actuator/health` 匿名，其余 `/api/**` 要求已认证（设计草案中的 `/api/admin/**` 前缀方案未采用）。`AdminInitializer` 冷启动 seed 默认 admin。


## 4. 数据库设计（草案）

```sql
-- books
id BIGINT UNSIGNED PK AUTO_INCREMENT
isbn VARCHAR(20) NOT NULL              -- 书号，唯一
title VARCHAR(200) NOT NULL            -- 书名
total_copies INT NOT NULL              -- 总册数
available_copies INT NOT NULL          -- 可借阅数量
price_cents INT NOT NULL               -- 价格（分）
version INT NOT NULL DEFAULT 0
created_at / updated_at DATETIME(3)
UNIQUE KEY uk_books_isbn (isbn)
KEY idx_books_title (title)
CHECK (available_copies BETWEEN 0 AND total_copies), CHECK (price_cents >= 0)
```

```sql
-- readers
id BIGINT UNSIGNED PK AUTO_INCREMENT
name VARCHAR(50) NOT NULL
phone VARCHAR(20) NOT NULL
status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE'   -- ACTIVE / FROZEN
created_at / updated_at DATETIME(3)
UNIQUE KEY uk_readers_phone (phone)
```

```sql
-- accounts（登录凭证与角色，与 readers 一对一可选关联）
id BIGINT UNSIGNED PK AUTO_INCREMENT
username VARCHAR(50) NOT NULL
password_hash VARCHAR(100) NOT NULL      -- BCrypt
role VARCHAR(16) NOT NULL                -- READER / ADMIN
reader_id BIGINT UNSIGNED NULL           -- READER 账号指向 readers.id；ADMIN 为 NULL
status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE'
created_at / updated_at DATETIME(3)
UNIQUE KEY uk_accounts_username (username)
UNIQUE KEY uk_accounts_reader (reader_id)
FK → readers(id)
```

```sql
-- loans
id BIGINT UNSIGNED PK AUTO_INCREMENT
book_id BIGINT UNSIGNED NOT NULL
reader_id BIGINT UNSIGNED NOT NULL
borrowed_at DATETIME(3) NOT NULL
due_at DATETIME(3) NOT NULL
returned_at DATETIME(3) NULL
status VARCHAR(16) NOT NULL            -- BORROWED / RETURNED
fine_cents INT NOT NULL DEFAULT 0      -- 归还时结算
KEY idx_loans_reader (reader_id, status)
KEY idx_loans_book_due (book_id, due_at)
FK → books(id) / readers(id)
```

```sql
-- reservations
id BIGINT UNSIGNED PK AUTO_INCREMENT
book_id BIGINT UNSIGNED NOT NULL
reader_id BIGINT UNSIGNED NOT NULL
status VARCHAR(16) NOT NULL            -- WAITING / READY / FULFILLED / CANCELLED / EXPIRED
created_at DATETIME(3) NOT NULL        -- 排队依据
ready_at DATETIME(3) NULL
hold_until DATETIME(3) NULL
KEY idx_res_queue (book_id, status, created_at)   -- 队首查询
FK → books(id) / readers(id)
```

存储引擎 `InnoDB`，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`。

## 7. 待定项（第二版决议，详见 `.docs/第二版实施方案.md`）

- 图书「可借阅数量」与「总册数」是否允许在新增后调整：首版不开放接口。→ **第二版开放**：`PATCH /api/books/{id}/copies`（ADMIN），下架校验总册数 ≥ 在借数 + 活跃预留数。
- 读者 `status=FROZEN` 的触发条件：首版仅作为人工设置字段。→ **第二版联动**：逾期归还自动冻结；缴清罚款且无逾期在借时自动解冻；另提供管理员手动冻结/解冻接口。
- 是否需要「借阅上限」：首版不限制。→ **第二版实现**：`book.loan.max-borrowing`（默认 5），借出（含履约）时校验，读者行锁防并发超限。
- 未缴清罚款的处理：首版只结算不闭环。→ **第二版闭环**：`loans.fine_status`（NONE/UNPAID/PAID），缴纳接口 + 未缴清禁借（借书与预约均拦截）。

## 8. 第一版实现修订（2026-10-19，范围评审结论）

- **新增 `PUT /api/books/{id}`**：接口清单原本只有增删查，但录错数据（书名/价格）将无法更正（删除又被未还借阅拦截），故补修改接口；仅更新 `title`/`priceCents`，走 `version` 乐观锁（冲突重读重试 3 次），`total_copies` 调整仍不开放。
- **删除图书增加预约保护**：除「存在未归还借阅拒绝」外，存在活跃预约（WAITING/READY）同样拒绝（40903）。
- **默认账号来源**：不做注册接口，`AdminInitializer`（ApplicationRunner）启动时若无 ADMIN 则创建 `admin`（密码取环境变量 `ADMIN_PASSWORD`，缺省 `admin123`，BCrypt 存储），并在日志告警提示改密。
- **并发口径补充**：借/还/预约流转入口对 books 行 `SELECT FOR UPDATE` 串行化多步队列操作；库存扣减/回补仍用条件更新（`available_copies > 0` / `< total_copies`）兜底，与 §3.5 不冲突。
- **Boot 4 适配实录**：Jackson 3（`tools.jackson` 包名）；Flyway 需用 `spring-boot-starter-flyway`（裸 `flyway-core` 在 Boot 4 模块化后不带自动配置）；`TestRestTemplate` 移至 `spring-boot-resttestclient` 且不再自动注册 bean，集成测试改用 `RestTemplate(JdkClientHttpRequestFactory)` + 自定义 errorHandler（默认 HttpURLConnection 实现会吞掉 401 响应体）；Testcontainers 2.0.5 的 `MySQLContainer` 已非泛型。

## 10. 第二版实现记录（2026-10-19，规则收口 + 权限收口）

依据 `.docs/第二版实施方案.md`（四项决策：未缴清罚款禁借 / 自助注册 / 上限可配置默认 5 / 不引入 springdoc）。

- **迁移**：`V2__loan_fine_status.sql`——`loans.fine_status`（NONE/UNPAID/PAID）+ 存量回填（已归还且罚款>0 → UNPAID）。
- **罚款闭环**：缴纳接口 `POST /api/loans/{id}/fine/pay`（ADMIN，40917 防重复缴）；借出与预约入口拦截 UNPAID（40914）；逾期归还自动冻结读者；缴纳后无待缴且无逾期在借自动解冻（手动解冻绕不过罚款禁借——拦截依据是 UNPAID 记录而非读者状态）。
- **借阅上限**：`book.loan.max-borrowing`（默认 5，≤0 不限）；借出（含履约）校验；借出入口对 `readers` 行 `SELECT FOR UPDATE` 串行化同一读者并发借阅，**固定先锁读者再锁图书**避免死锁。
- **数据归属**：`auth/AccessPolicy.assertSelfOrAdmin`——READER 只能操作 token 中自身 readerId 的资源（借/还/查记录/读者详情/预约/取消预约），越权 40300；`GET /api/loans` 对 READER 强制归属过滤。
- **注册/改密**：`POST /api/auth/register`（匿名，事务内建 readers + accounts，注册即签发 token，40915/40904）；`PUT /api/auth/password`（40002 旧密码错，新旧相同 40001）。
- **入库/下架**：`PATCH /api/books/{id}/copies`——行锁内校验新总册数 ≥ 在借数 + 未过期 READY 预留数（40916），可借数按差额同步增减，条件更新兜底。
- **读者管理**：`GET /api/readers`（分页，ADMIN）、`PUT /api/readers/{id}`、`PUT /api/readers/{id}/status`（手动冻结/解冻）。
- **新增错误码**：40002 / 40913 / 40914 / 40915 / 40916 / 40917（越权复用 40300，注册手机号重复复用 40904）。
- **验证**：58 个集成测试全绿（Testcontainers + Flyway 真 V1+V2 迁移，新增 5 个测试类 29 个用例，含越权、并发上限、冻结联动）；`tools/smoke.py` 扩至 30 步真实链路全通（注册→越权 403→借满 40913→入库→改密）。
- **接口规模**：14 → 21 个（+7），出入参变化：`LoanResponse` +`fineStatus`、`ReaderDetailResponse` +`unpaidFineCents`/`unpaidFine`。
