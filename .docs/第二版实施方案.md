## 1. P0-1 罚款闭环 + 逾期自动冻结

### 数据变更（V2 迁移）

```sql
-- V2__loan_fine_status.sql
ALTER TABLE loans
    ADD COLUMN fine_status VARCHAR(16) NOT NULL DEFAULT 'NONE' AFTER fine_cents;
-- 存量回填：已归还且有罚款 → UNPAID，其余 NONE
UPDATE loans SET fine_status = 'UNPAID'
WHERE returned_at IS NOT NULL AND fine_cents > 0;
```

状态机：`NONE`（借出中或无罚款）→ 归还时 `fine_cents > 0` 置 `UNPAID` → 缴纳置 `PAID`。

### 行为规则

1. **禁借**：借出（含预约履约路径）与发起预约前，校验读者存在 `fine_status = 'UNPAID'` 的借阅 → 抛新错误码 `40914`。
2. **缴纳**：`POST /api/loans/{id}/fine/pay`（ADMIN），`UNPAID → PAID`；非 UNPAID 拒绝。
3. **逾期自动冻结**：归还结算时 `overdueDays > 0` → 该读者 `readers.status = FROZEN`（借书入口已有 FROZEN 拦截，天然生效）。
4. **自动解冻**：缴纳罚款使读者**无 UNPAID 且无逾期在借**（`due_at < now AND status='BORROWED'`）→ 自动置 `ACTIVE`。管理员手动解冻见 §2.6。
5. 查询出口：`LoanResponse` 增加 `fineStatus`；`ReaderDetailResponse` 增加 `unpaidFineCents`（该读者 UNPAID 汇总）。

## 2. P0-2 借阅上限

1. 配置：`BookProperties.Loan` 改为 `record Loan(int days, int maxBorrowing)`，默认 `(30, 5)`；`application.yaml` 显式配 `book.loan.max-borrowing: 5`。
2. 校验：借出时 `COUNT(loans WHERE reader_id=? AND status='BORROWED') >= maxBorrowing` → 抛新错误码 `40913`。
3. 并发：借出入口新增对 `readers` 行 `SELECT FOR UPDATE`（与 books 行锁配合；**固定先锁读者再锁图书**，全路径一致避免死锁），防止同一读者并发借不同书超限。归还路径不加读者锁（不涉读者计数）。
4. 履约借出（READY）同样受上限约束：已满则拒绝借出，预约保持 `READY` 直到 `hold_until` 过期自动顺延（复用既有惰性机制，不为它加新状态）。
5. 预约发起**不校验**上限（排队无害，取书时再拦），只校验罚款。

## 3. P0-3 数据归属校验（READER 只能操作自己）

现状：SecurityConfig 仅图书写操作与新增读者限 ADMIN，其余已认证即可 → 任意 READER 可替任何人借/还/查/约。

方案：URL 规则不动，**业务层校验**（token 载荷已有 `role`/`readerId`）。新增 `auth/AccessPolicy` 组件，提供 `assertSelfOrAdmin(principal, readerId)`：

| 接口 | READER 行为 |
|---|---|
| `POST /api/loans` | `request.readerId` 必须等于自身，否则 `40300 FORBIDDEN` |
| `POST /api/loans/{id}/return` | 借阅单 `readerId` 必须是自身 |
| `GET /api/loans` | 不传 `readerId` 时强制过滤为自身；传他人 → 403 |
| `GET /api/readers/{id}` | 仅允许查自己 |
| `POST /api/reservations` | `request.readerId` 必须是自身 |
| `DELETE /api/reservations/{id}` | 预约必须是自身的 |
| `GET /api/books/**`、`GET /api/books/{id}/reservations` | 不限（书目与队列不含读者隐私字段） |

决策：越权返回 `40300`（不做 404 伪装，内部系统直白优先）；ADMIN 一切代办合法。

## 4. P0-4 自助注册与改密

1. `POST /api/auth/register`（匿名，加入放行清单）：`{username, password, name, phone}`。
   - 事务内：username 查重（新码 `40915`）→ phone 查重（复用 `40904`）→ 插 `readers` → 插 `accounts(role=READER, reader_id)`。
   - 密码 `@Size(min=6, max=50)`，强度从简（记录决策）。
   - 成功**直接签发 token**（注册即登录），返回 `LoginResponse`。
2. `PUT /api/auth/password`（已认证，全角色）：`{oldPassword, newPassword}`；旧密码错 → 新码 `40002`；新密码不得与旧密码相同（40001 校验失败）。
3. ADMIN 密码重置接口不做（超范围，忘记密码走重建流程）；`AdminInitializer` 启动告警保留。

## 5. P1 入库/下架与读者管理

1. `PATCH /api/books/{id}/copies`（ADMIN）：`{totalCopies}` 目标值。
   - 锁 books 行 → 校验新值 ≥ 在借数 + 未过期 READY 预留数，不足 → 新码 `40916`；
   - 条件更新 `total_copies = ?`、`available_copies = available_copies + delta`，version 乐观锁照旧。
2. `GET /api/readers?keyword=&page=&size=`（ADMIN）：分页列表（复用 `PageResult`）。
3. `PUT /api/readers/{id}`（ADMIN）：改 `name`/`phone`（phone 查重复用 40904）。
4. `PUT /api/readers/{id}/status`（ADMIN）：手动冻结/解冻 `{status: ACTIVE|FROZEN}`。

## 6. 新增错误码

| 码 | HTTP | 含义 |
|---|---|---|
| 40002 | 400 | 原密码错误 |
| 40913 | 409 | 超出借阅上限 |
| 40914 | 409 | 存在未缴清罚款，禁止借阅/预约 |
| 40915 | 409 | 用户名已存在 |
| 40916 | 409 | 总册数不能低于在借与预留之和 |

越权复用 `40300 FORBIDDEN`；注册手机号重复复用 `40904`。

## 8. 测试计划（预计 +22，总数 ~51）

- **越权（~7）**：READER 替他人借/还/查记录/看详情/约/取消 → 403；ADMIN 代办通过；READER 查列表自动过滤。
- **上限（~4）**：借满 5 本后第 6 本 40913；多线程并发借满不超限（复用并发测试模式）；还 1 本后可再借；履约借出遇上限被拒且预约保持 READY。
- **罚款闭环（~5）**：逾期归还 → UNPAID → 禁借 40914 → 预约同样 40914 → 缴纳 → 可再借；缴纳后无欠款且无逾期在借 → 自动解冻。
- **自动冻结（~2）**：逾期归还 → FROZEN → 再借 40905；有其他逾期在借时缴纳不解冻。
- **注册/改密（~6）**：注册成功直接可借书；用户名重复 40915；手机号重复 40904；密码过短 40001；改密后旧密码失效新密码可登录；旧密码错 40002。
- **入库/下架（~3）**：加册成功；减到低于在借+预留 40916；下架后 available 正确。
- 冒烟扩展（tools/smoke.py）：注册 → 借满 → SQL 构造逾期归还出罚款 → 禁借 → 缴纳 → 自动解冻 → 再借，一条龙断言。
