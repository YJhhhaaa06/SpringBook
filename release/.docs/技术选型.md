# 图书信息管理系统 — 技术选型与设计决定

> 依据：`.docs/原始需求.md`。接口明细见 `.docs/接口文档.md`；三个数据结构落点分别见《书名前缀联想（Trie）设计与落地》《顺序表与书号索引设计》《热门榜与TopK设计》。

## 1. 需求与交付范围

**核心功能**：图书信息（书名、书号、可借阅数量、价格）的插入、删除、检索；存储图书与借阅人信息；借阅与归还。
**扩展功能**：可借数量为 0 时允许预约；逾期未还罚款。

**实际交付**：在需求之上补齐了让系统真正可用的部分——身份与权限（ADMIN / READER，JWT）、读者自助注册与改密、图书修改与入库下架、读者管理、借阅上限、罚款闭环（待缴 / 已缴）、读者端与管理端页面。

**数据结构落点**（选做，但都接在主链路上，不是样例代码）：

| 落点 | 结构 | 解决的问题 |
|---|---|---|
| 书名前缀联想 | 字符 Trie | 逐键前缀查询不碰数据库 |
| 书号索引 | 有序顺序表 + 二分 | 按 id / ISBN 点查走内存，不占连接池 |
| 热门榜 top-K | 有界最小堆 + 双指针归并 | 不物化候选集，只排前 k |

**明确不做**：分布式 / 多实例部署、缓存中间件、消息队列、定时任务、全文检索与拼音联想、按小时的热度窗口、refresh token、前端构建链。理由见 §7。

**未采用**：

- **Spring Data JPA**：与 Boot 4.1.1 的 Hibernate 版本组合不匹配；且本项目大量使用条件更新、行锁与聚合 SQL，手写 MyBatis 更直接。

- **MapStruct**：DTO 转换数量有限，静态工厂方法更直观。
- **springdoc / knife4j**：接口文档手写即可，避免额外依赖与 Spring Framework 7 的适配不确定性。
- **前端框架 / 打包器**：页面数量有限，原生 ES Module 足够，省掉 Node 构建链。

## 3. 关键设计决定

### 3.1 金额一律以「分」为整数存储

- `books.price_cents`、`loans.fine_cents` 均为 `INT`，单位分。
- 罚款单价 0.5 元/天 = **50 分/天**；罚款 = 逾期天数 × 50，**封顶为该书的 `price_cents`**。
- 全程禁止 `float`/`double`；仅在出参时用 `BigDecimal.valueOf(cents).movePointLeft(2)` 转元。
- 逾期天数按「不足一天计一天」向上取整：`ceil((now - due_at) / 1 天)`。

### 3.2 借阅期限 30 天，可配置

`book.loan.days=30`，归还截止时间 = 借出时刻 + 30 天，落库到 `loans.due_at`（不做动态计算，便于后续改规则时历史数据不变）。

### 3.3 逾期状态不落库，按 `due_at` 派生

`loans.status` 只有 `BORROWED` / `RETURNED`；「是否逾期」由 `due_at < now && returned_at IS NULL` 实时判定，避免引入定时任务与状态不一致。罚款金额在**归还那一刻**结算并写入 `fine_cents`。

### 3.4 预约为 FIFO 队首优先

- 仅当 `available_copies = 0` 时允许预约，否则直接提示可借。
- 状态机：`WAITING → READY → FULFILLED`，旁路 `CANCELLED`、`EXPIRED`。
- 归还时：若队列非空，队首 `WAITING` 置 `READY`，并写入 `hold_until = now + 48h`（`book.reservation.hold-hours=48`）。
- `READY` 超过 `hold_until` 未取：置 `EXPIRED`，自动顺延下一位。采用**惰性清理**（在借书、还书、查预约时触发），不引入定时任务。
- 同一读者对同一本书只能有一条活跃预约（`WAITING`/`READY`），用服务层 + 事务内校验保证。

### 3.5 并发控制：条件更新 + 必要的行锁

借出：

```sql
UPDATE books SET available_copies = available_copies - 1
WHERE id = ? AND available_copies > 0
```

受影响行数为 0 即库存不足，抛业务异常。归还同理：`... + 1 WHERE id = ? AND available_copies < total_copies`。

`books.version` 是乐观锁，只用于「修改书名/价格」这类整行更新；冲突自动重读重试 3 次，仍失败返回 `40912`。

多步队列操作（借书、还书、预约流转）在事务内对 `books` 行 `SELECT FOR UPDATE` 串行化；借书还要对 `readers` 行加锁以校验借阅上限。**固定先锁读者、再锁图书**，避免两个读者并发互借时死锁。库存扣减/回补仍用条件更新兜底。

### 3.6 统一响应与异常

`Result<T> { code, message, data }`，成功 `code=0`；业务异常继承 `BizException` 携带 `ErrorCode`，由 `@RestControllerAdvice` 统一转换；参数校验失败映射为 `40001` 并返回字段级明细。

### 3.7 测试策略

- 集成测试用 Testcontainers 拉起 `mysql:8.4`，通过 `@ServiceConnection` 注入数据源，Flyway 在容器内真实执行 V1–V3 迁移。
- 覆盖重点：库存扣减并发（多线程抢最后一本）、归还触发队首 `READY`、罚款封顶、逾期天数向上取整、读者冻结与解冻、数据归属越权、借阅上限。
- 数据结构（Trie / 顺序表 / 堆）另有**不启 Spring、不连数据库**的纯单元测试，把边界条件与复杂度相关的语义单独盯住。
- 不使用 H2：方言与锁行为差异会掩盖真实问题。
- 前端用无头浏览器逐页渲染、真实点击并收集未捕获异常（`tools/ui_acceptance.py`）。

### 3.8 鉴权与权限

- **方案**：`spring-boot-starter-security` 提供过滤链与 `BCryptPasswordEncoder`，`java-jwt` 负责签发/校验，自定义 `OncePerRequestFilter` 解析 `Authorization: Bearer <token>`，不使用 Session（`SessionCreationPolicy.STATELESS`）。
- **账号模型**：独立 `accounts` 表（`username, password_hash, role, reader_id, status`）。`role` 取 `READER` / `ADMIN`；`READER` 通过 `reader_id` 关联 `readers`，`ADMIN` 为 `NULL`。读者身份与借阅资料分离，密码不进入业务表。
- **Token**：HS256，载荷含 `sub`(accountId)、`role`、`readerId`、`iat`、`exp`，有效期 2 小时，不做 refresh token。
- **密钥**：从环境变量 `JWT_SECRET` 读取；留空时回退到内置演示密钥并打印 WARN（便于课程演示），正式部署必须覆盖。
- **放行口径**：`POST /api/auth/login`、`POST /api/auth/register`、`GET /actuator/health` 匿名；图书新增/修改/删除/入库下架、读者新增/列表/资料修改/冻结解冻、缴纳罚款要求 ADMIN；其余 `/api/**` 要求已认证。
- **数据归属**：`AccessPolicy.assertSelfOrAdmin` —— READER 只能操作 token 中自身 `readerId` 的资源（借/还/查记录/读者详情/预约/取消），越权返回 `40300`，ADMIN 可代办。
- **默认管理员**：`AdminInitializer` 启动时若无 ADMIN 则创建 `admin`（口令取 `ADMIN_PASSWORD`，缺省 `admin123`，BCrypt 存储），并打日志提示改密。

### 3.9 借阅规则闭环

- **借阅上限**：`book.loan.max-borrowing`（默认 5，≤0 视为不限制），借出（含预约履约）时校验；读者行锁串行化同一读者的并发借阅。
- **罚款状态**：`loans.fine_status` 取 `NONE` / `UNPAID` / `PAID`；缴纳接口 `POST /api/loans/{id}/fine/pay`（ADMIN），重复缴纳返回 `40917`。
- **罚款禁借**：读者存在任一 `UNPAID` 借阅即禁止借书与预约（`40914`），与读者是否冻结无关；手动解冻绕不过这条。
- **冻结联动**：逾期归还自动置 `FROZEN`；缴清罚款且无逾期在借时自动解冻；另提供管理员手动冻结/解冻。
- **入库/下架**：`PATCH /api/books/{id}/copies` 直接给目标总册数，行锁内校验新总册数 ≥ 在借数 + 未过期 READY 预留数（`40916`），可借数按差额同步增减。

### 3.10 三个数据结构落点

| 落点 | 入口 | 选它的理由 |
|---|---|---|
| 字符 Trie | `GET /api/books/suggest` | 联想逐键触发，走 SQL 会持续占用连接池；前缀查询在 SQL 里虽能走 range 索引，但 Trie 把这次往返彻底去掉 |
| 有序顺序表 | `GET /api/books/{id}`、`/api/books/isbn/{isbn}` | 详情页与扫码取书是最高频的点查；索引让读路径不借连接、不开事务 |
| 有界最小堆 | `GET /api/books/hot` | 两条聚合已按 `book_id` 有序，归并后用 O(k) 内存取前 k，不物化候选集 |

三者都以「派生视图 + 事务提交后同步」的方式接入，权威数据始终在 MySQL。

## 4. 数据库设计

```sql
-- books
id BIGINT UNSIGNED PK AUTO_INCREMENT
isbn VARCHAR(20) NOT NULL              -- 书号，唯一
title VARCHAR(200) NOT NULL            -- 书名
total_copies INT NOT NULL              -- 总册数
available_copies INT NOT NULL          -- 可借阅数量
price_cents INT NOT NULL               -- 价格（分）
version INT NOT NULL DEFAULT 0         -- 乐观锁
created_at / updated_at DATETIME(3)
UNIQUE KEY uk_books_isbn (isbn)
KEY idx_books_title (title)
CHECK (available_copies BETWEEN 0 AND total_copies), CHECK (price_cents >= 0)
```

```sql
-- readers
id BIGINT UNSIGNED PK AUTO_INCREMENT
name VARCHAR(50) NOT NULL
phone VARCHAR(20) NOT NULL
status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE'   -- ACTIVE / FROZEN
created_at / updated_at DATETIME(3)
UNIQUE KEY uk_readers_phone (phone)
```

```sql
-- accounts（登录凭证与角色，与 readers 一对一可选关联）
id BIGINT UNSIGNED PK AUTO_INCREMENT
username VARCHAR(50) NOT NULL
password_hash VARCHAR(100) NOT NULL      -- BCrypt
role VARCHAR(16) NOT NULL                -- READER / ADMIN
reader_id BIGINT UNSIGNED NULL           -- READER 指向 readers.id；ADMIN 为 NULL
status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE'   -- ACTIVE / DISABLED
created_at / updated_at DATETIME(3)
UNIQUE KEY uk_accounts_username (username)
UNIQUE KEY uk_accounts_reader (reader_id)
FK → readers(id)
```

```sql
-- loans
id BIGINT UNSIGNED PK AUTO_INCREMENT
book_id BIGINT UNSIGNED NOT NULL
reader_id BIGINT UNSIGNED NOT NULL
borrowed_at DATETIME(3) NOT NULL
due_at DATETIME(3) NOT NULL
returned_at DATETIME(3) NULL
status VARCHAR(16) NOT NULL            -- BORROWED / RETURNED
fine_cents INT NOT NULL DEFAULT 0      -- 归还时结算
fine_status VARCHAR(16) NOT NULL DEFAULT 'NONE'  -- NONE / UNPAID / PAID
created_at / updated_at DATETIME(3)
KEY idx_loans_reader (reader_id, status)
KEY idx_loans_book_due (book_id, due_at)
FK → books(id) / readers(id)
```

```sql
-- reservations
id BIGINT UNSIGNED PK AUTO_INCREMENT
book_id BIGINT UNSIGNED NOT NULL
reader_id BIGINT UNSIGNED NOT NULL
status VARCHAR(16) NOT NULL            -- WAITING / READY / FULFILLED / CANCELLED / EXPIRED
created_at DATETIME(3) NOT NULL        -- 排队依据
ready_at DATETIME(3) NULL
hold_until DATETIME(3) NULL
KEY idx_res_queue (book_id, status, created_at)   -- 队首查询
FK → books(id) / readers(id)
```

存储引擎 `InnoDB`，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`。

## 6. 包结构

```
io.github.yjhhhaaa06.springbook
├── SpringBookApplication
├── common/          Result、PageResult、ErrorCode、BizException、GlobalExceptionHandler、AfterCommit、BookHitCount
```

业务按功能分包（package-by-feature），每个包内保持 controller/service/mapper/domain/dto 分层，避免全局扁平的三层结构。`ds/` 单独放数据结构，不反向依赖业务包。

## 7. 明确的边界

| 不做 | 原因 |
|---|---|
| 分布式 / 多实例 | 索引是进程内派生视图，多实例各持一份，共享成本不成比例 |
| 缓存中间件 | 本地索引已覆盖点查与联想；聚合查询直连 MySQL，规模未到 |
| 消息队列 / 定时任务 | 逾期由 `due_at` 派生，预约过期用惰性清理，不需要后台调度 |
| 全文检索 / 拼音联想 | 需求只要书名 / 书号检索；拼音需要外部词典，不是数据结构问题 |
| 按小时的热度窗口、时间衰减 | 业务口径没定，加了只是猜 |
| refresh token / 找回密码 | 2 小时过期后重新登录；账号体系以课程演示为边界 |
| 前端构建链 | 原生 ES Module 足够，静态资源直接打进 jar，少一层工具链 |
